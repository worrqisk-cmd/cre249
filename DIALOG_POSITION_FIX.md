# Положение каталога при закрытии изделия

## Причина, установленная до исправления

Измерения выполнялись в Chromium, без видео и скриншотов, на локальном Angular dev server. Данные — опубликованный снимок каталога через `tests/catalog-fixture.mjs`; страницы без авторизации. Снимались `scrollY`, DOMRect карточки и категорий, `innerWidth`, `documentElement.clientWidth`, ширина body, высота документа, изменения overflow, вызовы focus/scrollTo, popstate и события Angular Router через dev API.

1. `/catalog/` и `/item/:slug/` имеют разные routeConfig. Стандартная стратегия Router уничтожала Catalog при переходе между ними. Во время закрытия высота документа на мобильном viewport 390×900 временно падала с 3708 до 1408 px. При высоте viewport 900 браузер ограничивал scrollY значением 508. Для кураги наблюдалось 735 → 508 → 735, для «Молочной девочки» — 760 → 508 → 760. Последующий scrollTo восстанавливал конечную позицию, скрывая проблему от тестов, проверявших только результат после закрытия.
2. Снятие `body.style.overflow = hidden` возвращало обычную полосу прокрутки. Контрольный запуск headed Chromium под Xvfb с отключённым gutter показал ширину body 1425 → 1440 → 1425 при viewport 1440. Координата x карточки менялась 92.5 → 100 → 92.5 px. Это отдельный горизонтальный сдвиг.
3. Фокус карточки уже восстанавливался с preventScroll: измерения до и после focus не показали самостоятельной прокрутки. Встроенное scrollPositionRestoration Router не включено (`provideRouter(routes)`); событий Router Scroll не наблюдалось. Участвовали ограничение scrollY при уменьшении документа, браузерная история и явный scrollTo.
4. Блокировку overflow независимо снимали Catalog и ProductDialog. Кроме восстановления на NavigationEnd, Catalog планировал повторный restoreFocus через 50 ms.

## Исправление

- Catalog сохраняет экземпляр и DOM при переходах между каталогом, его категориями и открытыми из приложения изделиями. Прямые страницы изделий сохраняют самостоятельный режим; detach/cache маршрутов не используется.
- Режим самостоятельной страницы вычисляется из текущего slug. Категория сохраняется и при прямом входе в фильтрованный каталог; индикатор обновляется при изменении параметров маршрута.
- Только ProductDialog владеет блокировкой прокрутки и возвращает предыдущее значение overflow при уничтожении.
- `scrollbar-gutter: stable` сохраняет ширину страницы при скрытии полосы прокрутки. clientWidth может отражать наличие полосы, но ширина body и геометрия каталога остаются неизменными.
- Закрывающая кнопка и возвращаемая карточка получают фокус с preventScroll. Повторное восстановление через таймер удалено. Для сохранённого каталога scrollTo не вызывается; восстановление для других исходных страниц сохранено и защищено от устаревшего callback.
- Обратный перелёт измеряет текущую неподвижную карточку перед закрытием; сохранённые координаты остаются резервом для исходной страницы вне каталога.
- Длительности и анимация сохранены.

## Проверка

Production build, локальный сервер `http://127.0.0.1:8447/`, без SPA fallback. Headed Chromium под Xvfb с обычной полосой прокрутки: desktop 1440×900 и мобильная эмуляция 390×900. Это эмуляция телефона, не проверка на физическом устройстве.

`pnpm test:dialog-position` проверяет восемь последовательных открытий/закрытий четырёх изделий в каждом из четырёх сочетаний viewport и reduced motion: всего 32. Первое прохождение ближе к началу каталога, второе — с карточкой выше в viewport и большей прокруткой. Покрыты Escape, Back, кнопка закрытия с повторным Escape и немедленное закрытие при открытии. Дополнительно проверяется прямой вход в `/catalog/sweet/` и сохранение фильтра.

На каждом кадре и на границах focus, popstate и очистки overflow проверяются положение карточки, категорий, ширина body и scrollY. Конечные координаты перелёта сравниваются с реальной карточкой. Проверяется отсутствие scrollTo при возврате в каталог, preventScroll и очистка inert/overflow. Порог координат — 1 CSS px.

Результат: 32/32, отклонений нет. Desktop scrollY 0–652, мобильный 0–1201. Ширина body на desktop постоянно 1425 px, на телефоне 390 px. Фокус возвращается после снятия lock и не меняет scrollY. Например, desktop: начало закрытия 1728 ms, снятие overflow 2063.3 ms, focus 2075.2–2075.8 ms; scrollY и геометрия не изменились. В приложении задержки для этого не добавлены.

Команды и результаты:

- `HEADED=1 xvfb-run -a pnpm test:dialog-position` — 32/32 и фильтрованные маршруты.
- `pnpm test:motion` — открытие/закрытие, геометрия изображения, смена фото, прерывание перелёта, повторное закрытие, Back, reduced motion: прошли на 390 и 1440 px.
- `pnpm test:routing` — 23 HTTP-документа без SPA fallback, desktop/mobile reload, история, фокус, прокрутка, формы и WhatsApp: прошли.
- `pnpm test --watch=false` — 2 файла, 7 тестов, прошли.
- `pnpm build` — 23 prerender-маршрута, успешно.

Для повторной диагностики: `BASE_URL=http://localhost:8446/ POSITION_LOG=/tmp/dialog-position.json pnpm test:dialog-position`. Dev server дополнительно позволяет записать Router.events; production API Angular для этого не открывается. JSON содержит измерения и временные метки, медиазапись не используется.

SEO-исходники и файлы подтверждения поисковых систем не изменялись. Публикация и push не выполнялись.
