# Поисковая индексация milana-pechet.ru

Проверка: 2026-10-07. Область — техническая готовность к индексации и подключение Google/Яндекс; без аналитики и рекламы, без записи медиа.

## DNS и доступы

Авторитетные NS: ns1.timeweb.ru, ns2.timeweb.ru, ns3.timeweb.org, ns4.timeweb.org. Запросы TXT к ns1.timeweb.ru, 1.1.1.1 и 8.8.8.8 на момент проверки показывают только `v=spf1 include:_spf.timeweb.ru ~all`, без google-site-verification. DNS Timeweb connector отсутствует; в доступном браузере панель Timeweb требует входа. Cloudflare connector не обслуживает авторитетную зону Timeweb. SPF/MX/A/AAAA/CNAME/NS не менялись.

Search Console connector отвечает invalid_grant (OAuth refresh token отозван/истёк), ранее предоставленный scope — webmasters.readonly. В браузере нет авторизованной сессии Google. Требуются повторная OAuth-авторизация для отчётов и авторизованный кабинет для подтверждения/отправки sitemap/запроса индексации. Для доменного ресурса `sc-domain:milana-pechet.ru` нужен выданный Google TXT, отдельная запись в корне зоны; замена SPF или meta-тег не подтверждают доменный ресурс.

Яндекс connector отсутствует; сайт Вебмастера перенаправляет на авторизацию. Требуется авторизованная сессия либо выданные Яндексом имя/содержимое verification HTML-файла или meta-код для `https://milana-pechet.ru/`. Выдуманные/пустые коды не добавлялись. Приватные токены/пароли в чат не нужны.

## Проверенные страницы и изменения

До исправления robots.txt возвращал 404. Это не блокировало обход, но ссылка на sitemap не была объявлена в robots. Добавлен public/robots.txt: разрешён обход, объявлен HTTPS sitemap. Админка остаётся доступна для обхода, чтобы робот мог прочитать noindex в HTML. Её содержимое защищено Auth/RLS, а не robots.txt.

Все 23 страницы опубликованного sitemap проверены по исходному HTML до JavaScript: HTTP 200, base `/`, canonical совпадает с HTTPS URL, уникальные содержательные title и description, H1, содержание изделия и действие заказа, без публичного noindex и без github.io или /cre249/. Две оболочки /admin/ и /admin/login/ содержат noindex. HTTPS отвечает с валидным сертификатом; HTTP перенаправляет на HTTPS. Sitemap содержит главную, каталог, 4 категории и 17 изделий.

Добавлена команда pnpm test:seo и шаг workflow перед загрузкой Pages artifact. Проверяются эти свойства, robots.txt, совпадение sitemap с опубликованным снимком каталога и отсутствие оставшихся item-директорий. CHECK_CATALOG=1 дополнительно сверяет sitemap с актуальным публичным API Supabase (без чтения скрытых данных). BASE_URL позволяет повторить проверку на опубликованном сайте.

## Локальные сведения

Москва подтверждена владельцем в текущем диалоге и соответствует видимому содержимому. Публичная зона самовывоза/доставки не подтверждена; существующая формулировка предлагает согласовать получение и время при заказе. Адрес, часы, отзывы, цены и условия не добавлялись. Структурированные данные LocalBusiness/Offer не добавлялись без достаточных подтверждённых сведений.

## Обновление каталога

Изменения Supabase не запускают workflow автоматически. Для актуальных исходных HTML/sitemap/статических фото требуется полная сборка и новый Pages deploy: workflow_dispatch на main либо обычный merge/push main. Это требуется при добавлении/скрытии изделия, смене slug/категории, текста/фото/цен/начинок/доступности и публичных настроек. При unpublish пересобрать сразу: до замены artifact старый HTML и фото публичны. Новое изделие без пересборки может открываться через клиентский Router, но прямой URL ещё 404. Процедура описана в STATIC_PAGES.md.

## Оставшиеся этапы после предоставления доступов

1. Добавить настоящую Google TXT отдельной записью @, не меняя существующие DNS-записи; проверить все авторитетные NS и публичные резолверы, затем повторить Verify в доменном ресурсе.
2. Опубликовать настоящий verification-код Яндекса и выполнить подтверждение HTTPS-сайта.
3. Отправить https://milana-pechet.ru/sitemap.xml в оба кабинета; проверить статус обработки.
4. Google: URL Inspection главной → live test → запрос индексирования; Яндекс: переобход главной и доступные диагностика/страницы в поиске/проверка ответа сервера.
5. После OAuth-подключения проверить отчёты GSC. Эти операции не выполнены без доступа. Sitemap в robots.txt — возможность обнаружения, а не подтверждение отправки в кабинет. Отправка и переобход не гарантируют индексацию или позиции.
