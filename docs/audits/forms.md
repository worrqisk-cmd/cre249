## Статус API и границы

Официальная документация, проверенная перед миграцией:

- https://angular.dev/guide/forms/signals/comparison — стабильный API начиная с v22.
- https://angular.dev/guide/forms/signals/form-submission — submit, touched, submitting, блокировка параллельных отправок; по умолчанию pending-валидаторы не блокируют отправку. Здесь используются синхронные правила.
- https://angular.dev/guide/forms/signals/custom-controls — нестандартные контролы требуют соответствующих интерфейсов. Для загрузки файлов обёртка не вводилась: native binding не моделирует File/Storage lifecycle.

Это аудит пользовательских полей, а не общий аудит сайта. Проверены все input/select/textarea/form в src/app: вход, изделие, настройки, сообщение заказа, фокус фотографий, file input и выбор основной фотографии. Фильтры каталога и выбор начинки/фото — кнопки выбора, остаются вне форм.

## Единый подход и исключения

form(model, schema), FormField, inline FieldErrors, submit для операций. Ошибки API остаются отдельными alert-сигналами: это позволяет повторять отправку без изменения значений и без закреплённой серверной validation error. Изменения состояния формы сбрасываются через reset только при загрузке новой записи, создании, успешном сохранении или подтверждённом отказе от изменений.

Signal Forms отслеживает dirty/touched контролов; защита ухода сохраняет сравнение модели с сохранённым снимком. Это учитывает загрузку/удаление фото и отличает реальные несохранённые изменения от ввода с последующим возвратом исходного значения. Исходные строки начинок входят в снимок.

File input сохраняет явную проверку JPEG/PNG/WebP и лимит 8 МБ, uploading, ошибки и очистку input для повторного выбора. Выбор основной фотографии сохраняет radio и отдельный primary_photo. Это операции с файлами и галереей, а не повод создавать новый custom form control. Текстовые позиции фокуса фотографий мигрированы через applyEach.
